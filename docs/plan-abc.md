## Background

Two receipt datasets: SROIE (300 scanned receipts, root `results/`) and WildReceipt (200 phone photos, root `results_wild/`). The harness reads the **date and total** from a receipt image with a ladder of readers and escalates when deterministic checks flag an answer.

| Name | Reader | Results folder (SROIE 300 / WildReceipt 200) |
|---|---|---|
| T1 | local OCR + rules (RapidOCR; Tesseract as second witness) | `results/rapidocr`, `results/tesseract` / `results_wild/...` |
| T2 | local VLM, Qwen2.5-VL 3B on Ollama (about 28 s median here) | `results/qwen` / `results_wild/qwen` |
| T3 | cloud, cheap: Gemini 3.1 Flash-Lite | `results/gemini-lite` / `results_wild/gemini-lite` |
| T4 | cloud, strong: Gemini 3.6 Flash | `results/gemini` / `results_wild/gemini` |

Terms. **Code checks**: sanitizer, arithmetic identity, date plausibility, two-reader agreement (`src/harness/verify.py`). **Router**: the rule deciding when a receipt leaves T1. **Oracle**: a router that escalates exactly the receipts T1 gets wrong (upper bound). **Leak**: a tier's answer that is wrong on date or total while its flag list is empty (waterfall definition in `scripts/04_harness.py`). **Accepted precision**: share of auto-accepted answers with date and total both exact.

**Single input contract.** Correctness, flags, latency and cost for every analysis come from `<results_root>/harness/per_receipt.jsonl`, written by `04_harness.py` (`results_root` = `results` for SROIE, `results_wild` for WildReceipt). A may add raw T1 records for features only. Re-run order after any change to `04_harness.py`, `verify.py` or `normalize.py`: `04 -> 12 -> 14 -> 06 -> 10 -> 09`.

**Poster targets.** Edit only `poster/poster.template.html` and `poster/findings.json`; `poster/poster.html` and `poster/Park_Minwoo_MISM_ReceiptOCR.pdf` are regenerated by `10_fill_poster.py` then `09_render_poster.py`. Fig B = `results/figures/fig_sweep.png` drawn by `06_charts.py` (cloud share on x, accepted precision on y, one curve per router). Finding 2 = the escalation-signal claim below.

## Why

Run of 2026-10-31 (`results/harness/policies.json`): the oracle sends 27% of receipts to the cloud for 98.7% at $0.15 per 1,000 receipts; the rule router (both OCR readers agree and confidence >= 0.9) sends 56% for 95.7%. On WildReceipt the same run gives the rule router 84% cloud share for 87.0% precision (`results_wild/harness/policies.json`); A compares against these. The poster's central claim is therefore that **the escalation signal, not the model, is the bottleneck**. A asks whether a learned signal closes the gap, B asks how a time budget changes the decision when the local reader is slow, C asks what slipped past the checks.

## A. Learned escalation signal

**Question.** How much of the oracle gap does a learned score close, using only signals available at inference time?

**Inputs.** Label and T3 correctness from `per_receipt.jsonl` (label = T1 wrong on date or total, `t1.money_ok == false`); feature sources = the raw T1 records `results/rapidocr/<key>.json`, `results/tesseract/<key>.json` and the `signal` field of per_receipt. No ground-truth or cloud field is read for features; a unit test asserts the allowed source keys.

**Features** (`src/harness/features.py`, `features(rapid, tess, signal) -> dict`, with `feature_names`, `schema_version`, `source_fields` emitted alongside the model): RapidOCR `mean_conf`, `low_conf_share`, line count, count of money tokens in the bottom half of `lines`; Tesseract `mean_conf`; one 0/1 indicator per `rule_reasons` string defined in `src/harness/rules.py` (`total_not_found`, `total_multiple_strong_amounts`, `total_multiple_keyword_amounts`, `total_no_keyword_fallback_max`, `date_not_found`, `company_not_found`); `signal.agree`, `signal.complete`; absolute difference between the two readers' totals, capped at 100 (missing total on either side = 100). Bottom half = lines with index >= len(lines) // 2 in stored order; bounding boxes are not used. Aspect ratio and keyword strength are not stored in T1 records and are dropped.

**Model.** Logistic regression (scikit-learn, standardized, L2, default C). SROIE: 5-fold cross-validation, every prediction out of fold. Transfer: fit on all of SROIE, score WildReceipt.

**Replay rule.** Score >= threshold -> escalate: the receipt takes T3's recorded correctness, accepted blindly, exactly as `router` and `oracle` do (no code checks, no T4). Score < threshold -> T1's recorded correctness. The learned score replaces the whole T1 self-signal (agree + confidence). Sweep: every distinct out-of-fold score is a threshold. Baselines (router cloud share and precision) are read from `<results_root>/harness/policies.json`, never typed into code. Precision at the router share = precision of the threshold with the largest cloud share <= router share (no interpolation). Cloud share at router precision = smallest cloud share among thresholds with precision >= router precision; if none, write `not reached` and count the condition as failed. Rows whose ground truth lacks date or total (`money_ok` is null) are excluded from training and from the leak set.

**Outputs.** `<results_root>/learned_router/{model.json, curve.json, summary.md}`; `06_charts.py` reads `curve.json` and adds "learned router (out of fold)" to Fig B.

**Headline metrics.** (1) cloud share needed to reach the rule router's precision (SROIE 95.7%; Wild 87.0%); (2) precision at the rule router's cloud share (SROIE 56%; Wild 84%); (3) AUC out of fold; (4) the same on Wild with the SROIE-trained model.

**Acceptance.** The learned router *wins* if, out of fold on SROIE, precision at 56% cloud share > 95.7% AND cloud share at 95.7% precision < 56%. One of the two = partial. Either way the poster states the result.

**Run.** `python scripts/14_learned_router.py --results results` then `--results results_wild --fit-from results`.

## B. Latency-aware hedging

**Question.** When the local reader is slow, when should a receipt go to the cloud anyway?

**Policy `hedge`**, a branch of `decide(row, policy, params)` in `04_harness.py` (params = {'D': seconds, 'scale': float}; the existing policies take {'tau': float}); hedge rows report `latency_kind: wall` using per_receipt latencies and flags; there is no T1 stage, so the policy isolates the time-budget question.
1. t = 0: start T2. Its arrival time is `t2.latency_ms x scale`.
2. If T2's arrival time > D: fire T3 at t = D; its arrival time is `D + t3.latency_ms`. Otherwise T3 is never fired.
3. Answers are considered in arrival order; the first with an empty flag list is accepted. If every fired answer is flagged -> review. T4 is never called.
4. Cost = every fired call (cloud share counts fired T3 calls, accepted or not). Wait = arrival time of the accepted answer; for review rows, the last arrival.

Sweep D in {0, 2, 5, 10, 20, 30, 60, infinity} seconds and scale in {1.0 (this laptop, Vulkan backend), 0.25 (assumed CUDA-class GPU, labelled as an assumption)}.

**Sanity tests** (pytest on `decide()` with synthetic rows): D = 0 fires T3 for every receipt; D = infinity never fires T3 and review share = T2 flagged share.

**Outputs.** `<results_root>/hedge/{curve.json, summary.md}`, `results/figures/fig_hedge_<root>.png` (one per root) (x = D, y = cloud share and accepted precision, p50 wait as labels). Poster: one sentence in Results if it fits, else README only.

**Run.** `python scripts/04_harness.py --results results` and `--results results_wild --t1 rapidocr` (each writes hedge/ next to harness/), then `python scripts/06_charts.py`.

## C. Leak taxonomy

**Question.** What did the code checks miss?

**Inputs.** Every leaked row in `per_receipt.jsonl` for tiers t2, t3, t4 in both roots (run of 2026-10-31: SROIE 13 / 3 / 2, Wild 12 / 17 / 16 = 63 rows), plus the OCR `lines` from `results*/rapidocr/<key>.json`.

**Classes, assigned by code in this order.** `both_wrong` (date AND total wrong) is checked first; then `total_other_printed_amount` (predicted total equals a money token in the OCR lines that is not the truth, e.g. cash tendered or a subtotal); `total_digit_near_miss` (predicted and true total differ in one digit position or by a factor of 10); `total_other`; `date_day_month_swapped`; `date_other`; `both_wrong`.

**Outputs.** `<results_root>/leaks/leaks.jsonl` (key, tier, pred, gt, class, matched OCR token) and `leaks.md` (one row per leak, counts per class). README section; one clause on the poster if room.

**Run.** `python scripts/12_leaks.py --results results` and `--results results_wild`.
