1 · 한눈에 보는 구조

  1. 1영수증 이미지 입력파일 검증 후 축소 (클라우드 1,600px, 로컬 VLM 1,024px)
  2. 2T1 이 모든 영수증을 로컬에서 읽음RapidOCR 텍스트 + Tesseract 증인, 규칙으로 vendor / date / total
  3. 3T1 확신 → 자동승인 · 43.7%두 OCR 의 날짜·총액 일치 AND OCR confidence ≥ 0.9
  4. 4확신 없음 → T3 Gemini Flash-Lite · 56.3%이미지가 기계를 떠나는 유일한 단계. 코드 검증 통과 → 자동승인 (51.7%)
  5. 5T3 플래그 → T4 Gemini Flash · 4.7%플래그 0 → 자동승인 (0.3%)
  6. 6여전히 플래그 → 사람 검토 · 4.3%300장 중 13장
  7. B로컬 전용: 4단계가 T2 Qwen2.5-VL 로 · 56.3%플래그 0 → 자동승인 (37.3%), 플래그 → 사람 검토 (19.0%)
  8. ⚡Gemini 429 / 503 → Claude Haikufast-fail 1회, 연속 3회 실패 시 circuit breaker 60초

코드 검증 1-4 (정답 없이)
  1. sanitizer: NFKC, EN/KO/JA/ZH injection 패턴, 필드 화이트리스트, 타입
  2. arithmetic: subtotal + tax + tip + discount = total (허용오차 0.05, 결측은 0 아님)
  3. 날짜 타당성 (데이터셋 시기 안)
  4. two-reader: 모델의 총액·날짜가 OCR 텍스트에 있어야 함
검증이 잡은 것각 리더를 300장 전부에 단독으로 돌렸을 때: Flash-Lite 오답 8건 중 5건, Flash 6건 중 4건, 로컬 VLM 51건 중 38건을 플래그.
