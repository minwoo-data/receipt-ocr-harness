LLM reads, code verifies

A routing and verification harness for receipt OCR: when a cheap local reader is enough, when to escalate, and how much model error deterministic code catches

Code & results

1Problem

I built the receipt-OCR side of a production expense platform (20 employees, about 200 receipts a month) that cut reconciliation time by 90%+, as the sole engineer over 729 merged pull requests.

A vision LLM reads receipts well but grades its own work badly: its self-reported confidence is not evidence, and an auto-approval path built on it was rolled back. When is a cheap local reader enough, when should a receipt escalate, and how much error can code catch with no answer key?

2From production

  • Built a 90-receipt, 8-currency golden set by hand; benchmarked 7 LLMs on accuracy, stability, cost and latency.
  • Gemini-to-Claude fallback with a fast-fail budget: a 503 storm that pushed one receipt to 87 s now bounds at about 10 s.
  • +11% amount-extraction pass rate from fixing a validator that silently dropped 12 model-returned fields.

3Experiment

  • 300 scanned receipts (ICDAR 2019 SROIE) and 200 phone photos (WildReceipt). Exact match on date and total; scoring is code, never a model.
  • 43 synthetic adversarial receipts: future and ancient dates, arithmetic traps, prompt injection in English and Korean. Held out; gates are set on the natural data only.
Terms. Oracle router: a router that knows the answers and escalates exactly the receipts the local reader gets wrong; the ceiling any real signal can reach. Oracle gap: distance between that ceiling and the real router. Accepted precision: share of auto-accepted answers with date and total both right. Leak: a wrong answer the code checks accepted. AUC: area under the ROC curve of the learned score that predicts "the local reader is wrong", out of fold.

Code checks on every model answer (no answer key, no model confidence):
sanitizer: injection patterns in EN/KO/JA/ZH, field whitelist, types arithmetic: subtotal + tax + tip + discount = total; absent is not zero date plausibility two-reader agreement: the model's total and date must appear in the OCR text
Zero flags → auto-accept. Flagged → escalate one rung → still flagged → human review.
